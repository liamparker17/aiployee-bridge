## Cross-cutting constraints

- **Strict TS:** `strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess` are on. Use conditional spreads (`...(x ? { foo: x } : {})`) instead of `foo: x` when `x` may be `undefined`. Use `array[i]!` only when bounds are statically guaranteed.
- **No architect-tool imports.** This repo has zero runtime dependency on `architect-tool`; do not add any.
- **Wire format is sacred.** Snake_case stays on the wire, including `Transfered` (the platform misspelling) and `phone_numbers` (always array of E.164 strings). camelCase only on the DTO side.
- **`success === true` is the gate.** HTTP 200 with `success: false` is a failure — Transport already raises `ApiError` on that path, downstream code does not need to re-check.
- **`number` is not stable across saves.** Edges in the DTO must reference nodes by `uuid`. `normalize.ts` reallocates `number` on every `toWire`.
- **Sandbox-only for live tests.** Integration tests target only flow `b2deacdb-73d2-4b4e-b13a-b2de58dc7ebd` ("Architect test 1"), agent `3527076a-e3d2-4eb5-bfdb-498e02cde84f` (Tracey Test), and phone `+27877295318`. Tests that need to mutate the sandbox flow must restore it to its prior state on teardown.

## Task 1 — `src/normalize.ts` (DTO ↔ wire)

**Goal:** typed conversion between `FlowDTO` (from `src/dto.ts`) and the wire `SaveFlowRequest` (from `src/schema/flow.ts`).

**Exports (signatures load-bearing):**

```ts
export function toWire(flow: FlowDTO): SaveFlowRequest;
export function fromWire(
  flowMeta: { uuid: string; name: string; description: string },
  wireNodes: FlowNode[],
): FlowDTO;
```

**`toWire` rules:**

1. Allocate sequential `number` starting at 1 in the DTO's node array order. The server may renumber on read; do not pretend `number` is stable.
2. Nodes with `uuid: null` get a freshly minted `crypto.randomUUID()` so the DTO is internally consistent on the round-trip back.
3. For every node, generate sockets via `inputSocketId(number, i)` / `outputSocketId(number, i)`. The default socket count per node type is:
   - Triggers (`inbound_call`, `internet_call`, `event`, `now`): 0 inputs, 1 output.
   - `connect_call_agent`, `call`: 1 input, 2 outputs (index 0 = Completed, index 1 = Transfered).
   - All others: 1 input, 1 output as a baseline; expand to match the highest index any connection actually targets.
4. For each `ConnectionDTO`, find source/target by `uuid`. Resolve `fromOutput` via `resolveOutputIndex` (already in scope — accepts numeric or labelled). Push connections onto **both** sockets (source's output AND target's input), each connection referencing the other end's `node_number` + socket id.
5. Compute `data_key` via `dataKey(type, number)` for every node. The wire `data` block for the three known types is built from the DTO's `config`:

   | DTO config | wire `data` |
   |------------|-------------|
   | `inbound_call` | `{data_key, phone_numbers, cancel_prev_executing, google_sheets_sync_data: {use_google_sync, google_sheet_id, google_sheet_name}}` |
   | `connect_call_agent` | `{data_key, actions, connect_agent_params: {copy, type, uuid, prompt, phone_numbers}}` |
   | `call` | `{data_key, actions, max_concurrent_executing, retry_policy: {is_active, rules}, agent_params: {copy, uuid, prompt, phone_numbers}}` |
   | other (`RawConfig`) | `{data_key, ...config.raw}` (pass-through with a refreshed `data_key`) |

6. Final wire node:
   ```ts
   {
     uuid: string;            // never null
     name: string;
     type: NodeType;          // === config.kind
     status: number;          // from DTO; default 1
     number: number;          // freshly allocated
     position: [x, y];        // tuple from DTO.position
     inputs: Socket[];
     outputs: Socket[];
     data: <type-specific>;
   }
   ```

**`fromWire` rules:**

1. Build a `number → uuid` map from `wireNodes`.
2. For each wire node, emit a `NodeDTO` with `uuid`, `name`, `position: {x: pos[0], y: pos[1]}`, `status`, and `config` derived from the wire `data`. Use:
   - `inbound_call`: read `phone_numbers`, `cancel_prev_executing`, optional `google_sheets_sync_data` → DTO `googleSheetsSync: {enabled, sheetId, sheetName}` (only set if the wire object is present).
   - `connect_call_agent`: read `connect_agent_params` → `{agentUuid, agentType, copyAgent, prompt, phoneNumbers}`. `agentType` defaults to `"ai"`.
   - `call`: read `agent_params` and `retry_policy` analogously.
   - other: `{kind: type, raw: data}` (passthrough).
3. For every output socket of every wire node, for every `Connection` in that socket, emit a `ConnectionDTO`:
   - `fromNode`: source node's `uuid`
   - `fromOutput`: branch label if known for this type (`Completed` at index 0, `Transfered` at index 1 on `connect_call_agent`/`call`), otherwise the numeric index
   - `toNode`: `numberToUuid.get(conn.node_number)` — **silently drop** the connection if the target uuid isn't found (dangling edge; validators will catch on re-save)
   - `toInput`: parse the trailing `_<n>` off `conn.node_socket` (e.g. `"ID_21_0"` → `0`)
4. Do NOT emit duplicate connections — wire format already mirrors each connection on both sockets, so iterating outputs gives every edge exactly once.

**Avoid:**
- TypeScript pitfalls from the previous attempt: do NOT call `new Map(arr)` where `arr` is an array of objects. Build `[k, v][]` tuples explicitly: `new Map(numbered.map((x) => [x.uuid, x] as const))`.
- Don't expose `number` on the DTO. The DTO must round-trip without it being meaningful.

**Verification (must pass before commit):** `npx tsc -p tsconfig.json --noEmit` returns clean.

## Task 2 — Unit tests for `normalize.ts`, `validate.ts`, `transport.ts`

**Goal:** node:test tests covering the round-trip and validator rules without hitting the network.

**Setup:**
- Test runner: `node --test --import tsx tests/**/*.test.ts` (already wired in `package.json`).
- No third-party assertion library — use `node:test` + `node:assert/strict`.
- Tests live under `tests/` (excluded from tsconfig `include`, so they're transpiled by `tsx` at runtime).

**`tests/normalize.test.ts` — required cases:**

1. `toWire` happy path: 3 nodes (inbound_call → connect_call_agent → call, with Transfer branch back), check that:
   - Output has 3 wire nodes with `number` 1, 2, 3.
   - Each socket id matches the `ID_<n>_<i>` / `OD_<n>_<i>` pattern.
   - Connection between connect_call_agent's `Transfered` and call shows up on BOTH sockets, with `node_socket` matching the other end's id literally.
   - `data_key` is `<type>_node_<number>` for every node.
2. `toWire` with `uuid: null` on a new node: a uuid gets assigned and surfaces in the output.
3. `toWire` with an unknown `kind` (RawConfig, e.g. `kind: "split"` with arbitrary `raw`): the `data` block contains `data_key` plus the passthrough fields.
4. Round-trip: `fromWire(meta, toWire(dto).nodes)` returns a DTO whose nodes (by uuid) and connections (as a set of `{fromNode, fromOutput, toNode, toInput}` tuples, with branch labels normalised) match the input.
5. `fromWire` with a dangling target `node_number` (not in the map): the dangling connection is omitted, other connections survive.
6. Branch-label round-trip: `fromOutput: "Transferred"` (two-r spelling) → wire index 1 → `fromOutput: "Transfered"` (platform's one-r spelling) on the way back. Documented in a test assertion.

**`tests/validate.test.ts` — required cases:**

1. Empty flow → one issue: "no trigger node".
2. Two trigger nodes → one issue on the second.
3. Inbound Call with empty `phoneNumbers` → one issue with that node's uuid.
4. `connect_call_agent` with empty `agentUuid` → one issue with that node's uuid.
5. Connection referencing an unknown `toNode` uuid → one issue.
6. Valid 2-node flow → no issues.
7. `normalizeZaPhoneNumber`: `"0877295318"` → `"+27877295318"`, `"+27877295318"` unchanged, `"abc"` returned as-is.

**`tests/transport.test.ts` — required cases:**

1. Successful envelope: mock fetch returns `{success: true, code: 200, result: [1,2,3], errors: null}` → `request` returns `[1,2,3]`.
2. `success: false` envelope → throws `ApiError` with `code`, `errors`, and the message extracted from `errors` if it's a string or an object with `message`.
3. Non-JSON body (HTML error page) → throws `ApiError` whose `errors` is the truncated body text.
4. Network error (mock fetch throws) → propagates as a thrown error (not necessarily `ApiError`).
5. Bearer header is set; `Content-Type: application/json` is set only when there's a body.
6. Query params are appended; `undefined` values are skipped.

Inject `fetchImpl` via `TransportOptions` to avoid any real network calls.

**Verification:** `npm test` exits 0 with all tests passing.

## Task 3 — Phase 3: tool-group façade (`src/tools/`)

**Goal:** the high-level functions the MCP server (Task 4) and library callers will use. Each is a thin layer over `Client`. Library-usable without MCP.

**Files:**

- `src/tools/flows.ts`
- `src/tools/agents.ts`
- `src/tools/numbers.ts`
- `src/tools/index.ts` (barrel)

**Function inventory:**

```ts
// flows.ts
import type { Client } from "../client/index.js";
import type { FlowDTO } from "../dto.js";
import type { ValidationIssue } from "../validate.js";

export interface FlowSummary {
  uuid: string;
  name: string;
  status: "Active" | "Inactive";
  modifiedAt: string | null;
}

export async function listFlows(c: Client): Promise<FlowSummary[]>;
export async function getFlow(c: Client, uuid: string, meta?: Partial<FlowSummary>): Promise<FlowDTO>;
export async function updateFlow(c: Client, flow: FlowDTO): Promise<void>; // local-validate then save
export async function validateFlowLocal(flow: FlowDTO): Promise<ValidationIssue[]>;

// agents.ts
export interface AgentSummary { uuid: string; name: string; }
export async function listAgents(c: Client): Promise<AgentSummary[]>;

// numbers.ts
export type PhoneNumberKind = "inbound" | "outbound" | "human";
export interface PhoneNumberInfo {
  number: string;         // E.164
  kind: PhoneNumberKind;
  label: string;
  ownerAgentUuid?: string;
}
export async function listPhoneNumbers(c: Client): Promise<PhoneNumberInfo[]>;
```

**Rules:**

1. **Discovery for `listFlows`.** The Yii listing page is server-rendered HTML; `/v1/flows` is presumed but unverified. Implementation:
   - First call `c.transport.request({method:"GET", path:"/flows"})`.
   - If it throws `ApiError` with `httpStatus === 404`, fall back to scraping `https://aiployee.jobix.ai/flows` HTML for `<a href="/flows/<uuid>">` and the row's name/status/modified-at columns. Log the fallback once via `onRequest` (or `console.warn`) so the operator can see it.
   - Map either source into `FlowSummary[]`.
2. **`getFlow`** calls `c.getFlowNodes(uuid)`; combines with the optional `meta` (or a fresh `listFlows` lookup if `meta` not provided) to build a `FlowDTO`. The wire `/v1/flows/<uuid>/nodes` does NOT return name/description, so `meta` is necessary; document this.
3. **`updateFlow`** runs `validateFlow(flow)`, throws an `Error` with `JSON.stringify(issues)` if any issue has `severity: "error"`, then calls `toWire(flow)` and `c.saveFlow(...)`. Re-fetch is the caller's responsibility — after `saveFlow` returns the server may have renumbered.
4. **`listAgents`** wraps `c.listAgents()`. Each `DropdownOption` returns `{uuid: option.value, name: option.label}`. The `value` IS the agent uuid (verified in recon).
5. **`listPhoneNumbers`** calls all three pool variants in parallel (`Promise.all`), tags each entry with `kind`, dedups by `(number, kind)`, and includes `ownerAgentUuid` when the variant returns it (`outbound`). The dedup-by-(number, kind) deliberately keeps cross-kind duplicates so the LLM can see that the same number is available for both inbound and outbound on the same agent.

**Verification:** typecheck clean. (Tests against the live tenant happen in Task 6.)

## Task 4 — Phase 4: MCP server + auth CLI

**Goal:** a runnable MCP stdio server that exposes the Task 3 functions as tools, plus a one-time `auth` subcommand.

**Files:**

- `src/mcp-server.ts` (default executable per `package.json` `bin`)
- `src/auth-cli.ts` (called when arg[0] is `auth`)

**`mcp-server.ts` outline:**

```ts
#!/usr/bin/env node
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { Client } from "./client/index.js";
import * as flows from "./tools/flows.js";
import * as agents from "./tools/agents.js";
import * as numbers from "./tools/numbers.js";
import { FlowDTO } from "./dto.js";
```

The first argv-handling step is: if `process.argv[2] === "auth"`, delegate to `auth-cli.ts` and return. Otherwise start the MCP server.

**Tools to register** (each with a zod input schema and a JSON-schema input/output spec built from the zod schema):

| Tool name | Args | Returns |
|-----------|------|---------|
| `list_flows` | none | `FlowSummary[]` |
| `get_flow` | `{uuid}` | `FlowDTO` |
| `update_flow` | `{flow: FlowDTO}` | `{ok: true}` (after local validation passes and save succeeds) |
| `validate_flow` | `{flow: FlowDTO}` | `ValidationIssue[]` |
| `list_agents` | none | `AgentSummary[]` |
| `list_phone_numbers` | none | `PhoneNumberInfo[]` |

Construct one `Client` via `Client.fromAuthFile()` at server startup; reuse for every tool call. On `auth.json` missing, the server's startup fails fast with a clear error message instructing `aiployee-bridge auth`.

**`auth-cli.ts`** — parses `--token <value>` and optional `--api-base <url>`, calls `saveAuth`, prints the resolved path. Reads from stdin if `--token -` is passed.

**Verification:** `npm run build && node dist/mcp-server.js auth --token TEST` writes a file. `node dist/mcp-server.js` starts and prints the MCP handshake on stdio.

## Task 5 — Phase 5: integration tests against the sandbox

**Goal:** End-to-end tests against the real `aiployee.jobix.ai` tenant, gated by an env var so they don't run in normal `npm test`.

**File:** `tests/integration.test.ts`

**Gating:** `process.env.AIPLOYEE_BRIDGE_LIVE === "1"` — bail out with a skip if unset.

**Sandbox-only invariants (the tests MUST refuse to operate outside these):**
- `flowUuid === "b2deacdb-73d2-4b4e-b13a-b2de58dc7ebd"`
- All agent uuids referenced === `"3527076a-e3d2-4eb5-bfdb-498e02cde84f"`
- All phone numbers === `"+27877295318"`
- No call to `set_flow_status` with `"Active"`.

**Bench sequence (from the recon handoff):**

```
1. listFlows()                                            → "Architect test 1" appears
2. getFlow(b2deacdb-...)                                   → DTO returned, at least the trigger present
3. validateFlowLocal(<that flow>)                          → no issues
4. updateFlow(<that flow with a node renamed>)             → success
5. getFlow(b2deacdb-...)                                   → rename persisted
6. updateFlow(<restore original name>)                     → success (teardown)
```

**Restoration:** before any mutation, snapshot the original DTO; in a `try/finally`, write it back on teardown so a failed assertion never leaves the flow in a mutated state.

**Verification:** `AIPLOYEE_BRIDGE_LIVE=1 npm test` runs all 6 steps end-to-end with no leftover state on the tenant.
